# Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Copied files sync end-to-end encrypted: copy files on a computer (or share them on Android) and they can be pasted, saved or shared on the other devices; the web UI downloads them.

**Architecture:** A new clip kind `file` inside protocol 2. One clip holds every selected file; the sealed payload lists `files: [{name, size, mime}]` in blob order and each file is one chunked blob (`BlobCipher`, release 1's format). The server only sees "file clip, N blobs, about S bytes" and enforces `PP_MAX_FILE_MB`. Desktop downloads incoming live file clips into `<data dir>/files/<clipId>/` and puts the file list on the clipboard; Android downloads only on demand (Copy, Save, Share); the web UI offers a download button per file.

**Tech Stack:** .NET 10 / ASP.NET Core / Avalonia 12.1.4 / xUnit; Kotlin, OkHttp, Compose, Robolectric (JDK 21); browser ES modules + WebCrypto, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-01-e2e-rich-text-files-design.md`, section "3. Files", plus "Protocol version gate" and "Content encryption". The spec orders rich text before files; the owner asked for files first. Files are additive within protocol 2 and don't touch rich text, so this plan ships files alone (ruling F0). Ignore everything about `rich`.

## Global Constraints

- **Protocol changes are additive and optional** (CLAUDE.md). Wire kind string `"file"`. `ServerLimitsDto` gains `fileMb` with a default of 25 when missing; `ClipDto` gains an optional `files` that the server never sets (clients fill it after decoding, as they do `text`/`width`/`height`). Release-1 apps already show unknown kinds as "Update PrivatePaste to see this clip" and never apply them; keep it that way.
- **Payload:** `files: [{ "name": string, "size": integer, "mime": string }]` in blob order, inside the sealed payload. No `text` for file clips. `blobCount == files.length`, no thumbnail.
- **Hash** (spec, verbatim): `ContentHash.ForFiles(files)` = lowercase hex of SHA-256 over UTF-8 `"f:"` followed, for each file in order, by `name + "\0" + size + "\0" + sha256hex(content) + "\n"`. `size` is the decimal byte count (invariant culture), `sha256hex` lowercase hex. The server sees the keyed hash as for every kind.
- **Limit:** total plaintext size up to `PP_MAX_FILE_MB` (default 25). Over it nothing syncs and the app says `Files over 25 MB aren't synced` with the current limit. At most **100 files** per clip (ruling F1); more → `Too many files. Copy at most 100 at once.`
- **Folders** in the selection are skipped. Only folders → nothing syncs and the app says `Folders aren't synced.`
- **Old server:** if server-info `kinds` lacks `"file"`, file copies aren't sent and the app says `Update your PrivatePaste server to sync files.`
- **Offline:** file clips are never queued (ruling F2): on a transient upload failure (offline, 5xx) the app says `Couldn't send the files. Copy them again when you're online.` (Android: `share them again`).
- **Names from another device are untrusted.** Every platform turns a payload name into a safe leaf name with the same rules (ruling F3): take the part after the last `/` or `\`; drop control characters (< 0x20, 0x7F) and `<>:"|?*`; trim trailing dots and spaces; if the result is empty, `.` or `..`, use `file`; if the stem is a Windows reserved name (`CON PRN AUX NUL COM1-9 LPT1-9`, case-insensitive), prefix `_`; cut to 200 UTF-16 units keeping the extension. Clashes inside one clip, and in Downloads, get ` (2)`, ` (3)` … before the extension. Test vectors for this live in `docs/e2e-test-vectors.json` under `"safeFileName"` (Task 1) and every platform must pass them.
- **Decryption writes to `<name>.part` and renames** only after the final chunk authenticates; a failed or tampered download leaves no file.
- **MIME:** the sender fills `mime` from the OS when it has one (Android `ContentResolver.getType`), else from the extension with a small shared table (ruling F4): `pdf application/pdf, txt text/plain, csv text/csv, json application/json, zip application/zip, png image/png, jpg/jpeg image/jpeg, gif image/gif, webp image/webp, svg image/svg+xml, mp4 video/mp4, mp3 audio/mpeg, doc application/msword, docx application/vnd.openxmlformats-officedocument.wordprocessingml.document, xls application/vnd.ms-excel, xlsx application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, ppt application/vnd.ms-powerpoint, pptx application/vnd.openxmlformats-officedocument.presentationml.presentation`, else `application/octet-stream`. Receivers never trust `mime` for anything but labelling (the web UI downloads every file as `application/octet-stream`).
- **Row text** (all UIs): first file's name; ` +N more` when there are more; then the total size formatted `0 B`, `12 KB`, `3.4 MB` (1 KB = 1024 B, one decimal under 10 MB/KB values, none above). Example `report.pdf +2 more · 3.4 MB`. Search matches every file name.
- **Kind icon** `branding/ui-icons/kind-file.svg` (Task 1), 24×24 stroke icon, path `M14 3H7a2 2 0 0 0-2 2v14a2 2 0 0 0 2 2h10a2 2 0 0 0 2-2V8z M14 3v5h5`, mirrored on each platform like the other kind icons (`DESIGN.md`).
- **Anti-goals:** no file name, content or size per file reaches the server, a log or a crash report in plaintext; the Windows popup never takes the focus for Save (`PopupWindow.KeepsFocusBelow`); never log key presses or typed text.
- UI copy: plain, sentence case, as written in this plan. `TreatWarningsAsErrors` is on. Tests come with every behaviour change; new UI gets a render/screenshot check in both themes.

## Review Focus

1. **A received name with path parts or a reserved name** (`../../evil.exe`, `C:\x\a.txt`, `CON.txt`, `a<b>.txt`) lands inside the clip's own folder or Downloads under a safe name and never escapes it. Tests: Task 1 vectors, Task 4 `Materialize_keeps_hostile_names_inside_the_clip_folder`, Task 3 `safeFileName` node test, Task 6 `ClipFileStoreTest.hostileNamesStayInside`.
2. **Echo:** a file clip applied to the desktop clipboard is read back by the watcher and must not upload again. Test: Task 4 `Applied_file_clip_is_not_uploaded_again`.
3. **Mixed selection:** files plus folders → only the files sync; only folders → `Folders aren't synced.` and nothing uploads. Tests: Task 4 `Folders_are_skipped` / `Only_folders_notify_and_upload_nothing`.
4. **Empty and duplicate files:** a 0-byte file round-trips (one empty final chunk); two files named `report.pdf` from different folders land as `report.pdf` and `report (2).pdf`. Tests: Task 2 `Empty_file_clip_is_accepted`, Task 4 `Files_round_trip_between_two_devices` (includes both).
5. **Interrupted download** (network drop or tampered blob mid-file) leaves no partial file and a retry downloads again. Tests: Task 4 `Tampered_blob_leaves_no_file`, Task 6 `ClipFileStoreTest.failedDecryptLeavesNothing`.
